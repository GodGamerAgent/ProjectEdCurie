# EdCurie demo walkthrough

The previous full project is on GitHub branch `future` at `3fa8a2f`. Use `main` for the demo.

1. Sign in as an assigned teacher. Create or open a course. In **Students**, add an approved institute email, name, date of birth and enrollment date. Verify that editing a student updates the course roster.
2. In **Topics**, add a chapter or topic. Upload a PDF, Markdown, or text file (or paste text), choose a processing mode — **Only questions**, **Only theory**, or **Both** — and select **Save and process resource**. Export PowerPoint slides to PDF first.
   - *Lab sheet, Only questions*: the question bank lists each extracted exercise with its verbatim source text, page, and an answer labelled **Answer from document** or **AI-proposed answer · review before use**. If the file has no exercises, the card says so.
   - *Class Theory Sheet, Only theory*: the **Resource summary** appears directly on the card with headings, definitions, formulas and `Source: page N` references. Zero questions is a complete result; publish it.
   - *Class Slides, Both*: the summary appears, plus any exercises. Without exercises, practice questions labelled **AI-generated from theory** with a source page are added.
   - Edit the summary (**Edit summary**) or any question and answer in the split live-preview editor. **Reprocess from start** keeps teacher-edited items. **Generate coding exercise** drafts a Python or JavaScript exercise; it is offered to students only when its reference solution passes every test (**Review tests and solution** to inspect or edit). Publish the reviewed resource.
3. In **Onboarding**, tick problems in the **Academic problem bank** and **Add selected to baseline**, or use **Generate variants from this problem** / **Generate from this summary**. Generate learning preference questions (explanation preferences and study habits; open-ended, unscored). Every generation takes a count and custom instructions, and its results are saved straight into the editable baseline draft. Edit or add custom questions. Use **Generate expected answer** on one academic question, tick several and **Generate answers for selected**, or **Generate all blank answers**; suggestions fill blank answers only (tick **Replace existing answers** to overwrite) and unclear questions are flagged for review. A flagged question (for example one with two parts) offers **Convert to multiple choice with AI**, or use **Convert flagged to multiple choice**; check the four options and the letter, or **Undo conversion**. Nothing is saved until you save or publish. **Publish baseline** sends what is in the editor; if it cannot publish, it names the missing question type or the numbered question that needs an answer.
4. In **Timetable**, add a weekday slot with the day, hour and minute selectors, a date range and timezone. Use **Get AI help** to suggest slots and load one into the form for review before saving.
5. Sign in as the enrolled student. Open the course and complete its academic and learning preference questions. Published topics are available after submission.
6. Open a topic and select **Learn** (the published summary is shown and the tutor teaches from it) or **Practice** (pick a question from the bank, or ask the tutor for one). Try a suggested reply, a custom text answer, one photo and one short voice message. Open a coding exercise: edit the starter code, **Run sample tests**, then **Submit solution** — check an accepted run, a wrong answer on a hidden test (input stays hidden), a compile error and an infinite loop (time limit exceeded).
7. If needed, verify deleting a resource removes it from the topic and deleting a course enrollment removes the student's course access. Resource history is retained in the database.

Run `npm run build` and `npm run test:isolated` for local verification. The latter uses a disposable database and mocked provider replies. Confirm real Groq generation, photo input, voice capture and transcription in Replit before presenting them.
